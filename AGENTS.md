# AGENTS.md

## Communication and ownership

- Communicate with the repository owner in Ukrainian unless the owner requests another language.
- Execute clear implementation requests directly; ask only when an irreversible external action or an ambiguous product decision requires it.
- Do not edit this file without explicit owner approval. Keep repository-specific rules here and do not add AI attribution, generated-by markers, watermarks or AI commit trailers.

## Project boundaries

- `esphome/grid-monitor.yaml` is the source of truth for firmware behavior and entity names.
- The ESPHome device is the backend. The Home Assistant frontend must not duplicate measurement, outage, tariff or counter logic.
- Preserve the distinction between unavailable ESP/PZEM states and a confirmed inverter state.
- Keep secrets in `esphome/secrets.yaml` only; never commit credentials, tokens or real local network values.

## HACS card architecture

- The installable frontend artifact is the root-level `grid-monitor-card.js`, registered as `grid-monitor-card`.
- Keep the card dependency-free: vanilla JavaScript, Web Components and Home Assistant's existing `hass` object only.
- Keep `hacs.json` accurate: `filename` must point to the root card and `content_in_root` must remain `true`.
- Do not add a custom integration merely to make HACS recognize the repository; ESPHome already provides the device integration.
- The native YAML dashboard remains a supported fallback and must not be removed when the card changes.

## UX invariants

- Preserve the dark navy/neon visual language: cyan-blue live data, green healthy state, amber inverter state and red quality alarms.
- The card must be responsive in narrow Android Home Assistant layouts as well as desktop masonry layouts.
- User-facing labels and statuses require a localization dictionary. Support Ukrainian and English; allow an explicit `language` override and otherwise follow the Home Assistant locale when available.
- Missing, `unknown` and `unavailable` entities must render a clear placeholder and must never throw or break the entire card.
- Destructive or state-changing buttons must call only the configured Home Assistant entity service and require confirmation where appropriate.

## Entity conventions

- Default entity IDs use the ESPHome slug `grid_monitor` and follow Home Assistant's lower-case entity IDs.
- Allow per-entity overrides in card configuration so devices with a different ESPHome name remain usable.
- New firmware entities must be reflected in the card, native dashboard coverage check and documentation.

## Validation

Run from the repository root before push:

```bash
node --check grid-monitor-card.js
python3 - <<'PY'
import json
json.load(open('hacs.json'))
print('hacs.json: OK')
PY
git diff --check
```

Also run the ESPHome-secret-aware YAML parser and dashboard/entity coverage check when firmware or dashboard mappings change. Do not claim live Home Assistant validation unless it was actually performed.

## GitHub workflow

- Inspect `origin/main` and open PRs before changes.
- Use a focused feature branch and conventional commits.
- Keep firmware, frontend, documentation and tests understandable in the same change when they form one installable feature.
- Open a PR with a concise summary and validation evidence. Merge only after checks pass, then verify the merge commit and final files on `main`.
- Do not force-push or rewrite shared history. Delete merged feature branches when appropriate.
